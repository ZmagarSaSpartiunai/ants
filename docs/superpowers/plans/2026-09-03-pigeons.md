# Голуби: мультиплеєр-артилерія — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Другa гра на тому ж хості — покрокова артилерія між голубами на телефонах, де снаряд обирається через те, що голуб з'їв.

**Architecture:** Раунди, а не безперервний такт. Сервер збирає постріли раунду й розсилає їх одним пакетом; кожен клієнт програє ту саму чисту фізику з тим самим зерном. Лобі (коди, місця, хост, боти) відділяється від симуляції «Мурашника» і стає спільним для обох ігор. Хост лишається одним процесом на одному порту.

**Tech Stack:** TypeScript, npm workspaces, Node + `ws`, Canvas 2D, Vite, `node --test`.

---

## Межі цього плану

Задача покриває кілька незалежних підсистем. Тут розписані **тільки Фази 0 і 1**
— рефакторинг хоста і чиста симуляція голубів. Обидві дають робочий, перевірений
результат самі по собі.

Фази 2–6 (клієнт, кімнати, полиця, акаунти, оплата) описані як межі й рішення,
але **свої плани отримають окремо**, коли Фаза 1 буде на місці. Писати покрокові
завдання для оплати зараз — це вигадувати код, який залежить від рішень, які ще
не ухвалено.

## Що вже є: чесна оцінка структури

Перевірено на диску, не з пам'яті.

**Добре, і краще, ніж здається:**

- `server/src/index.ts` уже **хост ігор, а не сервер мурах**. Там таблиця
  маршрутів `/` → полиця, `/ants/` → гра, `/luna/` → окремий файл, і коментар
  прямо каже: «one process carries a small shelf of games».
- Правило чистоти `shared/` тримається **компілятором**: у `shared/tsconfig.json`
  стоїть `"lib": ["ES2022"]` без `DOM`. Симуляція фізично не може торкнутись вікна.
- Ворота (`gate.ts`) закривають і сторінку, і сокет — не половину.
- Детермінізм і `tools/lockstep.mjs` — готова методика ловити розсинхрон.

**Що заважає другій грі — п'ять конкретних місць:**

| # | Місце | Проблема |
|---|---|---|
| 1 | `server/src/index.ts:196` | `new WebSocketServer({ path: '/ants/ws' })` — прив'язано до **одного** шляху. Другій грі сокета не дістанеться. |
| 2 | `server/src/room.ts` | `Room` — це лобі **плюс** такт мурах в одному класі. Голубам потрібне лобі, а такт мурах — ні. |
| 3 | `server/src/db.ts` | `recordMatch` пише підсумок мурах, схема під одну гру. |
| 4 | назви | `@ants/*`, `ANTS_PASSWORD`, `ants.service`. Хост у костюмі мурашника. |
| 5 | немає акаунтів | Спільний пароль — це не особа. Підписка без особи неможлива. |

**Рішення щодо назв (пункт 4): не чіпати зараз.** Перейменування працюючої
розгорнутої гри — це ризик без жодної віддачі сьогодні. Воно стає одним
механічним проходом пізніше, коли друга гра вже доведе, що спільного насправді.
Витягувати спільне на **другому** використанні, не на першому.

## Архітектурні рішення

### D1. Раунди з детермінованим повтором, а не лockstep

«Мурашник» тикає 20 разів на секунду, бо потік мурах безперервний. Постріл
голуба — подія, а не потік. Тому:

- клієнт шле один пакет за раунд: `{ food, angle, power }` — десятки байтів;
- сервер збирає постріли всіх, **сортує за номером місця** і розсилає раунд;
- кожен клієнт проганяє ту саму чисту фізику й бачить те саме.

Це переносить сильну сторону проєкту (чистий `shared/`) і викидає найважче
(безперервну синхронізацію). Перепідключення = переслати список раундів і
програти їх з нуля — це мілісекунди.

### D2. Вітер — функція від (зерно, раунд), а не стан генератора

```ts
windFor(seed, round)   // чиста функція, без стану
```

Клієнт, що перепідключився на 7-му раунді, рахує вітер сам і не мусить
відтворювати історію генератора. Це те, на чому зазвичай і розходяться.

### D3. Одночасні раунди, не по черзі — **потребує твого рішення**

Рекомендую: всі ціляться разом, постріли злітають разом. Ніхто не чекає, матч
удвічі коротший, і дітям це веселіше. Запасний варіант — класична черга як у
«Хробаках», якщо на грі виявиться, що каша нечитабельна.

**Фази 0 і 1 від цього не залежать** — фізика й таблиця їжі однакові. Рішення
потрібне на Фазі 3.

### D4. Ніякого руйнівного ландшафту у версії 1

У «Хробаках» земля — бітова маска, з якої вигризаються дірки. Це найбільше
джерело розсинхрону і найбільший тиск на пам'ять телефона.

Замість неї — **дискретні предмети**: парасолька, маркіза, димар, мотузка з
білизною. Предмет цілий або зламаний, одне число на предмет. Дітям читається
краще (видно, що саме ти зламав), синхронізується тривіально, і коштує вдесятеро
менше. Маску можна додати пізніше за тією ж моделлю повтору.

### D5. Шов для акаунтів зараз, оплата — ні

Створюється `entitlements.ts`, який сьогодні повертає «все безкоштовно». Кожне
місце, яке колись питатиме «чи має ця людина доступ до цієї гри», питає його
**вже зараз**. Тоді оплата стане одним модулем, а не переписуванням.

Будувати оплату наосліп — марна робота: вибір провайдера має податкові й
юридичні наслідки, і це твоє рішення, не моє.

### D7. Один процес, окремий модуль — а не окремий сервіс

Ти сказав «на тому ж сервері, тільки окремо». Тлумачу як **окремий код, спільний
процес**, і ось чому: на машині вже крутиться Caddy для панелі, оголошений як
`:8080`, тобто відповідає на **будь-який** Host. Другий сервіс на другому порту
означав би другий запис у тунелі й другий systemd-юніт заради того, що і так
розділяється шляхом.

Голуби дістають власний сокет (`/kaka/pigeons/ws`), власний пакет
(`@pigeons/shared`) і власний модуль на сервері. Спільними лишаються тільки
процес, ворота і лобі.

Якщо ти мав на увазі саме **окремий процес** — скажи, це змінює Задачу 0.2:
замість монтування шляху буде другий юніт і другий запис у `config.yml` тунелю.

### D6. Полиця стає дворівневою

Ти сказав: на `games` буде какульна гра, а всередині вже види. Отже:

```
/                     полиця: Мурашник · Луна · Какульки
/kaka/                какульна полиця: Голуби · Гнойовик · Зоопарк
/kaka/pigeons/        гра
/kaka/pigeons/ws      її сокет
```

Через це маршрутизація (Фаза 0, Задача 1) робиться таблицею, а не ланцюжком
`if`. Інакше через три гри її вже не читатимеш.

```ts
import assert from 'node:assert/strict';
import { createServer } from 'node:http';
import { WebSocket } from 'ws';
import { attachUpgrade, mountSocket } from './sockets.js';

/** Starts a throwaway server on a free port and returns its address. */
function listen(): Promise<{ port: number; close: () => void }> {
  const http = createServer((_req, res) => res.writeHead(404).end());
  attachUpgrade(http, () => true);

  return new Promise((done) => {
    http.listen(0, '127.0.0.1', () => {
      const addr = http.address();
      const port = typeof addr === 'object' && addr ? addr.port : 0;
      done({ port, close: () => http.close() });
    });
  });
}

test('each mounted path gets its own connections', async () => {
  const seen: string[] = [];
  mountSocket('/ants/ws', () => seen.push('ants'));
  mountSocket('/kaka/pigeons/ws', () => seen.push('pigeons'));
  const server = await listen();

  await new Promise<void>((done) => {
    const a = new WebSocket(`ws://127.0.0.1:${server.port}/ants/ws`);
    a.on('open', () => { a.close(); done(); });

  await new Promise<void>((done) => {
```

Create `server/src/sockets.ts`:

```ts
import { Server } from 'node:http';
import { IncomingMessage } from 'node:http';
import { Duplex } from 'node:stream';
import { WebSocket, WebSocketServer } from 'ws';

/**
 * One WebSocket server, many games.
 *
 * `ws` can bind itself to a single `path`, which was enough while the box ran
 * one game. A second game needs a second path, so the upgrade is handled here
 * and dispatched by pathname instead.
 */
const wss = new WebSocketServer({ noServer: true, maxPayload: 16 * 1024 });
const routes = new Map<string, (ws: WebSocket, req: IncomingMessage) => void>();

/**
 * @param path exact pathname, e.g. '/kaka/pigeons/ws'
 * @param onConnect called once per accepted socket
 * @return void
 */
export function mountSocket(path: string, onConnect: (ws: WebSocket, req: IncomingMessage) => void): void {
  routes.set(path, onConnect);
}

/**
 * @param http the server whose upgrades to take over
 * @param allowed decides whether this request may open a socket at all
 * @return void
 */
export function attachUpgrade(http: Server, allowed: (req: IncomingMessage) => boolean): void {
  http.on('upgrade', (req: IncomingMessage, socket: Duplex, head: Buffer) => {
    const path = new URL(req.url ?? '/', 'http://localhost').pathname;
    const onConnect = routes.get(path);
    // An unknown path must be closed, not left half-open: a hanging upgrade
    // holds a socket until the kernel gives up on it.
    if (!onConnect || !allowed(req)) {
      socket.write('HTTP/1.1 404 Not Found\r\n\r\n');
      socket.destroy();

      return;
    }
    wss.handleUpgrade(req, socket, head, (ws) => onConnect(ws, req));
  });
}
```

```ts
export interface Seat {
  /** null while the seat is empty or held by a bot. */
  ws: object | null;
  name: string;
  bot: boolean;
}

export class Lobby {
  readonly seats: Seat[];
  private readonly created = Date.now();

  constructor(readonly code: string, slots: number) {
    this.seats = Array.from({ length: slots }, () => ({ ws: null, name: '', bot: false }));
  }

  /**
   * @param ws the arriving socket
   * @param name what the player typed, possibly empty
   * @return the seat index, or null when the lobby is full
   */
  join(ws: object, name: string): number | null {
    const i = this.seats.findIndex((s) => !s.ws && !s.bot);
    if (i < 0) return null;
    this.seats[i] = { ws, name, bot: false };

    return i;
  }
  // ... leave, isHost, slotOf, roster, setBot, empty, stale
}
```

```ts
/**
 * Wind is a pure function of (seed, round), not the next number out of a
 * running generator.
 *
 * A player whose phone dropped the connection at round 7 can work out round 7's
 * wind without replaying the six rounds before it. A stateful generator would
 * make that impossible, and mismatched weather is exactly the kind of drift
 * that never shows up in a log.
 */
export function windFor(seed: number, round: number): number {
  let h = (seed ^ Math.imul(round + 1, 0x9e3779b9)) >>> 0;
  h = Math.imul(h ^ (h >>> 16), 0x85ebca6b) >>> 0;
  h = Math.imul(h ^ (h >>> 13), 0xc2b2ae35) >>> 0;
  h = (h ^ (h >>> 16)) >>> 0;

  return (h / 0xffffffff) * 2 - 1;
}
```

```ts
import { FOODS } from './food.js';
import { GRAVITY, Prop, SHOT_DT, SHOT_MAX_T, Shot, THROW_SPEED } from './types.js';

export interface Point {
  x: number;
  y: number;
}

export interface Flight {
  /** Every integrated position, for the client to draw the arc. */
  points: Point[];
  end: Point;
  /** Which prop stopped it, if any. */
  hitProp: number | null;
  bounced: number;
}

/**
 * @param prop the prop to test
 * @param p the point to test against it
 * @return whether the point is inside the prop's box
 */
function inside(prop: Prop, p: Point): boolean {
  return p.x >= prop.x && p.x <= prop.x + prop.w && p.y >= prop.y && p.y <= prop.y + prop.h;
}

/**
 * Flies one shot to where it stops. Pure: the same arguments always give the
 * same flight, on any machine, which is what lets every client replay a round
 * from a handful of bytes.
 *
 * @param from where the bird stands
 * @param shot what it threw and how
 * @param props the props that may stop it
 * @param wind -1..1, from windFor()
 * @return the whole flight
 */
export function flyShot(from: Point, shot: Shot, props: Prop[], wind: number): Flight {
  const food = FOODS[shot.food];
  const speed = THROW_SPEED * food.speed * Math.max(0, Math.min(1, shot.power));
  let x = from.x;
  let y = from.y;
  let vx = Math.cos(shot.angle) * speed;
  let vy = Math.sin(shot.angle) * speed;
  const points: Point[] = [{ x, y }];
  let bounced = 0;
  let hitProp: number | null = null;

  for (let t = 0; t < SHOT_MAX_T; t += SHOT_DT) {
    vx += wind * food.drag * 60 * SHOT_DT;
    vy += GRAVITY * SHOT_DT;
    x += vx * SHOT_DT;
    y += vy * SHOT_DT;
    points.push({ x, y });

    const struck = props.find((p) => p.intact && inside(p, { x, y }));
    if (struck) {
      if (bounced < food.bounces) {
        // Reflect off the face it came through, and lose some speed to it.
        bounced++;
        vy = -vy * 0.55;
        vx *= 0.8;
        y += vy * SHOT_DT;
        continue;
      }
      hitProp = struck.id;
      break;
    }
  }

  return { points, end: { x, y }, hitProp, bounced };
}
```

```ts
import { FOODS } from './food.js';
import { flyShot, Flight } from './physics.js';
import { windFor } from './rng.js';
import { Bird, MatchState, Prop, Shot } from './types.js';

/** Where each bird perches, in seat order. */
const PERCHES: { x: number; y: number }[] = [
  { x: 120, y: 220 },
  { x: 680, y: 220 },
  { x: 240, y: 120 },
  { x: 560, y: 120 },
];

export interface RoundResult {
  round: number;
  wind: number;
  flights: Flight[];
}

/**
 * @param seed the match seed, shared by every client
 * @param players how many birds, 2..4
 * @return a fresh match
 */
export function createMatch(seed: number, players: number): MatchState {
  const birds: Bird[] = [];
  for (let i = 0; i < players; i++) {
    const perch = PERCHES[i];
    birds.push({ slot: i, x: perch.x, y: perch.y, hp: 100, busy: 0, alive: true });
  }
  const props: Prop[] = [
    { id: 1, x: 340, y: 200, w: 120, h: 22, kind: 'roof', hp: 60, intact: true },
    { id: 2, x: 300, y: 90, w: 60, h: 18, kind: 'awning', hp: 30, intact: true },
    { id: 3, x: 460, y: 90, w: 60, h: 18, kind: 'awning', hp: 30, intact: true },
  ];

  return { seed, round: 0, birds, props, over: false, winner: null };
}

/**
 * @param s the match, mutated in place
 * @param shots what each seat fired this round, in any order
 * @return what happened, for the client to play back
 */
export function resolveRound(s: MatchState, shots: Shot[]): RoundResult {
  const wind = windFor(s.seed, s.round);
  const flights: Flight[] = [];
  // Sorting by seat is what makes the round independent of who answered first.
  const ordered = [...shots].sort((a, b) => a.slot - b.slot);

  // Only a bird that actually fired keeps its timer; one whose shot was
  // ignored must still count down, or it would stay busy for ever.
  const fired = new Set<number>();

  for (const shot of ordered) {
    const bird = s.birds[shot.slot];
    if (!bird || !bird.alive || bird.busy > 0) continue;
    const food = FOODS[shot.food];
    if (!food) continue;

    const flight = flyShot({ x: bird.x, y: bird.y }, shot, s.props, wind);
    flights.push(flight);
    bird.busy = food.digest;
    fired.add(bird.slot);

    for (const other of s.birds) {
      if (!other.alive) continue;
      const dx = other.x - flight.end.x;
      const dy = other.y - flight.end.y;
      const dist = Math.hypot(dx, dy);
      if (dist > food.blast) continue;
      // Full damage at the centre, nothing at the rim.
      other.hp -= food.power * (1 - dist / food.blast);
      if (other.hp <= 0) {
        other.hp = 0;
        other.alive = false;
      }
    }
    if (flight.hitProp !== null) {
      const prop = s.props.find((p) => p.id === flight.hitProp);
      if (prop) {
        prop.hp -= food.power;
        if (prop.hp <= 0) prop.intact = false;
      }
    }
  }

  for (const bird of s.birds) if (bird.busy > 0 && !fired.has(bird.slot)) bird.busy--;
  s.round++;

  const alive = s.birds.filter((b) => b.alive);
  if (alive.length <= 1) {
    s.over = true;
    s.winner = alive.length === 1 ? alive[0].slot : null;
  }

  return { round: s.round, wind, flights };
}
```

## Що НЕ входить свідомо

- **Руйнівний ландшафт** (D4) — дискретні предмети замість маски.
