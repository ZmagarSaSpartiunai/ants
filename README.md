# Мурашник

Тактична казуалка про стежки: вузли з числами, з'єднуєш пальцем, потік захоплює
чуже. Жанр — Tower War / Connect Towers, але з двома власними правилами.

**Статус: задум і скелет.** Ігрового коду ще немає.

## Дві фішки

**Стежку можна розірвати.** У всіх іграх жанру атакувати можна тільки вузли, і
через це гра — снігова куля: хто перший захопив три вузли, той уже не програє.
Тут ворожу феромонну стежку можна прогризти пальцем, і вузол, відрізаний від
мережі, перестає рости. У слабшого з'являється зброя: зайти в тил і порвати
постачання.

**Три типи юнітів із різними правилами**, а не з різними числами:

- **робочі мурахи** — швидкі й дешеві, але в зустрічному потоці гинуть;
- **жуки** — повільні, зате прориваються крізь зустрічний потік;
- **оси** — не користуються стежками взагалі, летять напряму.

Через це розрив стежок не всесильний: проти ос він не працює, і задушити їх
можна лише захопивши саме гніздо.

Подробиці й аргументи — у [DESIGN.md](DESIGN.md).

## Режими

- **Один проти бота** — крутиться повністю в браузері, без сервера й без мережі.
- **Кімната на 2–4** — код із шести символів, порожні місця займають боти.

## Технології

TypeScript на клієнті й на сервері, Canvas 2D, Node.js + `ws`, PostgreSQL, Vite.

Головне рішення — **одна симуляція на обидва боки**: правила лежать у `shared/`
і виконуються однаково в браузері й на сервері. Чому саме так і чому не PHP —
у [ARCHITECTURE.md](ARCHITECTURE.md).

## Розкладка

```
shared/    правила гри і бот. Без DOM і без мережі
client/    рендер, ввід, підключення
server/    кімнати, WebSocket, підсумки
db/        міграції
deploy/    systemd і фрагмент конфігу тунелю
```

## Сервер

Гра житиме на окремому **публічному** піддомені — панель за Cloudflare Access
не підходить, бо в гравців немає твоїх акаунтів. Схема, юніт і пастки —
у `~/Documents/work/creds/game-server.md` (поза репозиторієм, там доступи).
